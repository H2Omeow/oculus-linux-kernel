# VA48 用户态探针

在构建机离线编译（无需连接头显）：

```sh
gcc -std=c11 -O2 -Wall -Wextra -Werror -o va48_probe.host va48_probe.c
aarch64-linux-gnu-gcc -std=c11 -O2 -Wall -Wextra -Werror -static -o va48_probe.aarch64 va48_probe.c
```

仅在准备好的目标系统上运行对应架构的程序；成功返回 0，任一必要检查失败返回非零。
宿主机运行只验证宿主机，不代表 Quest 3S 的结果。

探针要求 64 位进程，读取真实系统页大小，每次映射 64 页，并检查每页全部字节。
每页使用不同的非零内容。固定地址覆盖跨越 `2^39`、`2^40` 的区间及结束于
`2^48` 的区间；每次都核对 `MAP_FIXED_NOREPLACE` 返回地址，从不使用 `MAP_FIXED`。
旧内核忽略该标志并返回其他地址、地址冲突（`EEXIST`）或边界不被允许，均算失败。
地址冲突可能需要在干净进程环境重测，不能单凭一次失败断定内核的 VA 宽度。

高地址测试检查 `mprotect`、`fork` 和 `waitpid`，子进程修改全部页面后，父进程
核对原内容仍保持，再恢复可写并重新写入。它验证实际写时复制与权限切换调用，
不包含通过故意写只读页面触发异常的权限强制测试。

已删除会触及全部页面的 256 GiB 测试；大虚拟预留本身也不能证明 VA48。
测试依次释放映射，数据页面最多约 128 页（写时复制期间父子进程各 64 页），
另需程序本身、页表和进程开销；4 KiB 页面时数据约 512 KiB。

全部通过只能证明**当前运行系统**允许这些指定用户态地址及其基本页表操作。
它不能证明全部 48 位地址空间均可用，也不能证明内核侧仍为 VA39、模块 ABI 兼容、
热切换成功或 Quest 硬件运行正常。常见 47 位用户地址宿主内核会拒绝接近 `2^48`
的映射，程序因此返回非零是预期的边界检测结果。
